# P5 BLUF Synthesis + Locale Number Hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the P5 "Hanoi Delivery Ratings" page one business-metric-backed
conclusion instead of four disconnected chart insights, and make every number
shown on the page survive a future dataset scale-up without manual edits.

**Architecture:** Cut the standalone rating-histogram section (section 01);
its chart survives, demoted into a new closing synthesis section placed after
section 04 and before the method/limits section. The synthesis's headline
number is a new restaurant-level aggregate (`complaintReach`, added to
`src/data/project5.js` via a new notebook cell) — "N restaurants have
`<category>` as their #1 named complaint" — instead of the review-level
`drag` figure already on the page. Every hardcoded dataset-size number
already in `src/locales/{en,vi}.json`'s `p5.*` strings is converted to i18next
interpolation sourced from `src/data/project5.js`, mirroring the
`{{pct}}` pattern `method_accuracy_text` already uses.

**Tech Stack:** React 18, react-i18next (interpolation `escapeValue: false`,
confirmed in `src/i18n.js`), Recharts, Vitest.

## Global Constraints

- Any user-facing string added or changed updates **both**
  `src/locales/en.json` and `src/locales/vi.json` in the same task — never one
  locale ahead of the other (CLAUDE.md).
- No literal dataset-size number (restaurant count, review count, share %,
  category name picked as "the top one", drag value) may be hardcoded in JSX
  or locale copy. Every number is interpolated via `t('key', {var: ...})`
  from a value computed off `src/data/project5.js`'s exports.
- No renumbering of existing sections 02, 03, 04 and no changes to their
  locale keys (`s2_*`, `s3_*` except the one specified interpolation change,
  `s4_*` except the one specified interpolation change). The method/limits
  section's `SectionTitle index` prop moves from `"05"` to `"06"` (a prop
  value only — its locale keys stay `s5_*`, unchanged) to make room for the
  new synthesis section at `index="05"`.
- Every derived number must ultimately trace back to a value inside
  `src/data/project5.js`, regenerated only by re-running
  `project5_analysis.ipynb` — never hand-edited in the generated file.

// Pure, data-shape-generic derivation helpers for Project 5's synthesis
// copy. None of these hardcode a category name, a count, or a dataset size —
// every one re-derives its answer from whatever series is passed in, so the
// page's conclusion stays correct after the underlying dataset is re-run at
// a different size. See docs/superpowers/plans/2026-07-27-p5-bluf-synthesis.md.

export function pickMaxGapPair(ratingPairs) {
  if (!ratingPairs || ratingPairs.length === 0) return null
  let best = ratingPairs[0]
  let bestGap = Math.abs(best.sf * 2 - best.foody)
  for (const pair of ratingPairs.slice(1)) {
    const gap = Math.abs(pair.sf * 2 - pair.foody)
    if (gap > bestGap) {
      best = pair
      bestGap = gap
    }
  }
  return { sf: best.sf, foody: best.foody }
}
```

export function pickTopByShare(complaints) {
  return complaints.reduce((best, row) => (row.share > best.share ? row : best))
}

export function pickTopByDrag(complaints) {
  const scored = complaints.filter(row => row.drag != null)
  if (scored.length === 0) return null
  const top = scored.reduce((best, row) => (row.drag > best.drag ? row : best))
  return { category: top.category, drag: top.drag }
}
```

- [ ] **Step 1: Insert the cell into the notebook**

Add a new Markdown cell followed by a code cell, placed directly after the
existing "Task 4: sizing the taxonomy" cell (the one whose output starts
`overall mean score 7.01`).

Markdown cell:

```markdown
### Task 5: restaurant-level complaint reach

`tax`/`drag` is review-level: it says how many *reviews* raise a complaint
and how much it costs when they do. It says nothing about how many
*restaurants* that reach touches. This cell answers that: for each
restaurant with at least one tagged complaint, find its "lead complaint" —
the category raised most often across that restaurant's own reviews — then
count restaurants per lead category.

Tie-break: if a restaurant has two categories tied for most-raised, keep
whichever has the higher taxonomy-level drag (costlier complaint wins the
tie over an arbitrary alphabetical pick).
```

Code cell:

```python
long_r = long.merge(rev[["review_id", "restaurant_id"]], on="review_id")

drag_rank = tax.set_index("category")["drag"].to_dict()

def lead_category(g):
    counts = g["category"].value_counts()
    top_n = counts.max()
    tied = counts[counts == top_n].index.tolist()
    if len(tied) == 1:
        return tied[0]
    return max(tied, key=lambda c: drag_rank.get(c, float("-inf")))

lead = (long_r.groupby("restaurant_id")
              .apply(lead_category)
              .rename("lead_category")
              .reset_index())

reach = (lead["lead_category"].value_counts()
             .rename_axis("category")
             .reset_index(name="n_restaurants")
             .merge(tax[["category", "drag", "n_reviews"]], on="category", how="left")
             .sort_values("n_restaurants", ascending=False))

print(f"reviewed restaurants total: {rev['restaurant_id'].nunique()}")
print(f"restaurants with at least one tagged complaint: {lead['restaurant_id'].nunique()}")
print(reach.to_string(index=False))
```

export function pickTopByReach(complaintReach) {
  if (!complaintReach || complaintReach.length === 0) return null
  const top = complaintReach.reduce((best, row) =>
    row.nRestaurants > best.nRestaurants ? row : best
  )
  return { category: top.category, nRestaurants: top.nRestaurants }
}
